# PARC2026 演習環境からの提出手順（`omni submit`）

| 項目 | 内容 |
| :---- | :---- |
| 版数 | 1.0 |
| 最終更新 | 2026-08-23 |

演習環境（JupyterLab）から、成果物を omnicampus に**直接**提出するための手順書です。学習済みモデルのような大きなファイルも、お手元の PC にダウンロードすることなく数分で提出できます。

**従来どおり omnicampus の Web 画面からも提出できます。** このコマンドは追加の選択肢で、どちらで提出しても結果は同じです。

---

## 0\. 全体像

```

  演習環境 GPU VM  ──── omni submit ────▶  omnicampus
                     8.3GB で 1〜3 分
```

演習環境から提出先まではクラウド内の通信になるため、ご自宅の回線を経由しません。実測で **1〜2 桁速く**なります。

### ⚠️ 先に押さえていただきたい 2 点

**1\. 提出すると採点回数を 1 回消費します。**

実行すると確認画面が出ます。課題名と残り回数を確認してから `y` を押してください。`N`（または Enter）でキャンセルすれば何も消費しません。

**まずは `--dry-run` から試すことをおすすめします。** アップロードも採点回数の消費も行わず、「何が提出されるのか」だけ確認できます（第 2 節）。

**2\. パスは `~/` から始まる絶対パスで指定してください。**

`./results` のような相対パスは、ターミナルやノートブックの現在位置によって指す先が変わります。存在しないパスを指した場合のメッセージが分かりにくいため（第 6 節）、`~/work/results` のように書くのが確実です。

---

## 1\. 使い方

JupyterLab のターミナル（Launcher → Terminal）で 1 行実行するだけです。**設定は不要**です。接続先やコース情報は環境変数として最初から入っています。

```shell
omni submit --assignment-id <課題ID> --path <提出したいディレクトリ>
```

例: `~/work/results` の中身を課題 1007 に提出する場合

```shell
omni submit --assignment-id 1007 --path ~/work/results
```

実行すると、指定したディレクトリを zip にまとめてから確認画面が出ます。

```
--- 提出内容の確認 ---
  課題        : 第1回 課題 (ID: 1007)
  提出サイズ  : 8.30 GiB
  分割数      : 86
  並列数      : 8
  提出回数    : これまで 3 回 (上限 5 回、残り 2 回)
  本日の提出  : 1 回 (上限 5 回、残り 4 回)

注意: 提出を完了すると採点回数を 1 回消費します。
続行しますか? [y/N]:
```

成功すると `提出を受け付けました (submissionId=...)` と表示されます。この表示が出れば、omnicampus の Web 画面の提出履歴にも反映されています。

---

## 2\. まず試す（採点回数を消費しない確認）

`--dry-run` を付けると、アップロードも採点回数の消費も行わず、zip の中身とサイズだけを確認できます。

```shell
omni submit --assignment-id 1007 --path ~/work/results --dry-run
```

### 練習用のサンプルで試す場合

```shell
# 300MB のダミーファイルを含むフォルダを作る
mkdir -p ~/submit-test/results
head -c 300M /dev/urandom > ~/submit-test/results/model.bin
echo '{"name":"test"}' > ~/submit-test/results/config.json

# 中身を確認（model.bin が 300M あること）
ls -la ~/submit-test/results

# 提出内容の確認だけ行う（送信しない）
omni submit --assignment-id 1007 --path ~/submit-test/results --dry-run
```

---

## 3\. ノートブックのセルから実行する

ノートブックでは確認画面を表示できないため、`--yes` を明示します。**`--yes` を付けると確認なしでそのまま提出まで進み、採点回数を消費します。**

```py
# まず中身を確認（送信しない）
!omni submit --assignment-id 1007 --path ~/work/results --dry-run
```

```py
# 実際に提出する
!omni submit --assignment-id 1007 --path ~/work/results --yes
```

---

## 4\. 中断してしまったら

アップロード中に Ctrl-C で止めた、接続が切れた、などの場合は `--resume` で続きから再開できます。アップロード済みの部分は再送されません。

```shell
omni submit --assignment-id 1007 --resume
```

再開できるのは中断から**約 11 時間以内**です。それを過ぎた場合は通常どおり実行し直してください（最初からのアップロードになりますが、提出としては同じです）。

---

## 5\. オプション一覧

| オプション | 説明 |
| :---- | :---- |
| `--assignment-id <ID>` | 提出先の課題 ID（必須） |
| `--path <DIR>` | 提出するフォルダ（既定: カレントディレクトリ） |
| `--dry-run` | 提出内容の確認のみ。送信も採点回数の消費もしない |
| `--yes` | 確認画面をスキップ（ノートブックから実行する場合は必須） |
| `--resume` | 中断したアップロードを再開する |
| `--parallel <1-16>` | 並列アップロード数（既定: 8。回線に余裕があれば上げられます） |
| `--version` | バージョン表示 |

`omni submit --help` でも確認できます。

### 何が zip に入るか

- `--path` で指定した**ディレクトリの中身**が、そのまま zip のルートになります（`cd <path> && zip -r out.zip .` と同じ形）  
- 次のものは**自動的に除外**されます: `.git` / `__pycache__` / `.ipynb_checkpoints` / `.venv` / `node_modules` / `*.pyc`  
- **シンボリックリンクは提出物に含まれません**（実行時に警告が出ます）。リンク先の実体を提出したい場合は、実ファイルとしてコピーしてから提出してください  
- zip は無圧縮です（モデルの重みなど圧縮の効かないデータで時間を無駄にしないため）。そのため **zip の作成に、提出サイズと同程度の空き容量**が必要です

## 6\. うまくいかないとき

| 症状 | 対処 |
| :---- | :---- |
| `--path 配下に提出できるファイルがありません` | **パスの指定間違いが最も多い原因です。** `ls -la <指定したパス>` で中身があるか確認してください。フォルダが空の場合、除外対象のファイルしか無い場合も同じ表示になります |
| `この課題は現在提出を受け付けていません` | 課題が非公開、受付開始前、または**締切を過ぎて**います。課題ページで受付期間をご確認ください |
| `この課題の提出回数の上限に達しています` | 提出回数を使い切っています |
| `本日の提出回数の上限に達しています` | 日次の上限です。日本時間の 0 時にリセットされます |
| `前回提出分の採点が進行中です` | 採点が終わってから再実行してください |
| `提出の確定処理が進行中です` | 同じ提出が処理中です。数十秒待つと自動で解決します |
| `認証に失敗しました` | セッションが終了しています。JupyterLab のサーバを起動し直してください |
| `環境変数が設定されていません` | このコマンドは**演習環境の中でだけ**使えます。お手元の PC では動きません |
| `ディスクの空き容量が不足しています` | zip の作成に提出サイズと同程度の空きが必要です。不要なファイルを削除してください |
| `omni: command not found` | VM を起動し直してください。コマンドは VM の起動時に取り込まれます |

**これらの「提出できない」系のエラーは、アップロードが始まる前に表示されます。** 8GB を送り切った末に失敗することはありません。

### 補足

- セッションの残り時間が 10 分を切っていると、提出前に警告が出ます。JupyterLab の通知バーから延長してから提出してください（警告のみで、提出自体は止まりません）  
- 作業用の zip は `~/.cache/omni-submit/` に作られ、**提出が成功すると自動的に削除**されます

## 7\. 速度の目安

8.3GiB の提出物での実測値です（演習環境の GPU VM から）。

| 並列数 | 実効レート | 所要時間 |
| :---- | :---- | :---- |
| `--parallel 4` | 約 65 MiB/s | 2 分 19 秒 |
| `--parallel 8`（既定） | 93〜160 MiB/s | 1 分 12 秒〜1 分 29 秒 |

zip の作成自体は 8.3GiB で約 12 秒です。所要時間のほとんどはネットワーク転送になります。

参考: ご自宅の回線（上り 10〜50Mbps）から同じ 8.3GB を送る場合は 25 分〜2 時間かかります。
